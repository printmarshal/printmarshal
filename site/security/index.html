Printer Security & Platform Hardening

Audit printer security. Protect management credentials.

PrintMarshal is built around two security principles: never report an unreadable printer setting as passing, and never write to a device without explicit operator action and read-back verification.

1. Baseline Policy & Unknowns 2. Port Probes & Certificates 3. Write Safeguards & Rotation 4. Encryption, RBAC & Audit
● Implemented 14 Baseline Rules · 43 Security Keys · 8 Operators

1. The 14-item Baseline policy and unknown-state scoring

PrintMarshal's canonical settings catalog defines 84 setting keys across 10 areas (internal/model/settings_catalog.go), of which 43 are tagged Security: true. The built-in Baseline policy evaluates 14 high-impact controls out of the box.

Standard SNMP (RFC 3805) and IPP do not expose every vendor-specific toggle (such as whether an administrator password is set or HTTP-to-HTTPS redirect is active). When no driver reports a key, PrintMarshal records status: "unknown" and excludes its weight from the compliance score denominator (internal/security/policy.go).

Why unknown is never counted as pass

On a standard SNMP/IPP printer where 5 of 14 Baseline rules are observable (Telnet disabled, FTP disabled, IPPS enabled, HTTPS enabled, SNMPv1/v2c enabled), the device scores 4 of 5 passing (81.8 weighted score) with 9 unknown items explicitly listed for review.

Active Probes & PKI Lifecycle

Port probes, TLS inspection, and certificate enrollment.

During an assessment, PrintMarshal inspects open TCP ports and TLS certificates directly on the device, and provides built-in PKI enrollment workflows.

1. Port & TLS Probes ● Implemented

security/portprobe checks TCP ports 21 (FTP), 23 (Telnet), 80 (HTTP), 443 (HTTPS), 515 (LPD), 631 (IPP), and 9100 (RAW). security/tlsprobe connects to 443 and 631 to record negotiated TLS version, cipher suite, leaf subject/issuer, SANs, self-signed status, and SHA-256 fingerprint.

2. CSR & Enrollment ● Implemented

Generate RSA-2048 CSRs (POST /api/devices/{id}/csr) and enroll certificates via the built-in encrypted root CA, EST (/.well-known/est/simpleenroll), or SCEP (POST /api/devices/{id}/certificates/enroll). Certificate checks (internal/security/certs.go) raise a warning alert at ≤ 30 days remaining and a critical alert at ≤ 7 days or expired.

3. Physical Installation ◌ Requires Driver

Enrollment and installation are distinct steps. PrintMarshal stores the issued certificate and encrypted private key (POST /api/devices/{id}/certificates/{issuedId}/install), but pushing the certificate onto a physical printer requires a vendor driver implementing driver.CertificateInstaller or manual upload in the printer's web UI.

2 Dry-run before apply

Profile applies, security remediations, and local CUPS syncs support non-destructive dry-run previews.

● Implemented Safeguards ◐ Device-Dependent Writes

3. Preview every change and verify writes

Configuration profile applies (POST /api/config/profiles/{id}/apply), ad-hoc writes (POST /api/devices/{id}/config/apply), policy remediations (POST /api/devices/{id}/security/remediate), and local CUPS queue syncs (POST /api/print-provider/sync) all support dryRun preview mode.

Accepted vs verified
After writing (internal/configmgmt/service.go), PrintMarshal re-reads the changed keys. Only keys whose read-back value matches the desired value are marked verified; write-only or unreadable keys are recorded as accepted (verified: false).
IPP TLS pinning
For authenticated IPP writes (Set-Printer-Attributes in internal/driver/ipp/), PrintMarshal prefers TLS endpoints, pins the printer's leaf certificate SHA-256 fingerprint (sha256:…) on first TLS contact, and aborts subsequent writes with ErrPinMismatch if the certificate changes.
Credential rotation
POST /api/security/rotate (internal/security/rotate.go) rotates snmpCommunity and adminPassword. It stages the new encrypted credential in the store *before* writing to the printer, deletes the staged credential if the printer cleanly refuses, keeps the staged credential with a warning on ambiguous network failures (timeout/EOF) so credentials are never lost, and verifies snmpCommunity with a read poll.
Direct actions
Two write actions execute directly without a dry-run preview: POST /api/devices/{id}/certificates/{issuedId}/install (pushing an issued cert via CertificateInstaller) and DELETE /api/print-provider/queues/{deviceId} (removing one managed local CUPS queue).
Control Plane Hardening

Credential encryption, RBAC, and SIEM export.

PrintMarshal protects stored device credentials, enforces role-based access across web and API routes, and streams audit events to your SIEM.

AES-256-GCM Secret Box (PM_SECRET_KEY) ● Implemented

All SNMP community strings, SNMPv3 auth/privacy passphrases, IPP credentials, internal CA private keys, device CSR private keys, and SCEP/EST secrets are encrypted at rest using AES-256-GCM with random 12-byte nonces (internal/secrets/secrets.go).

Secret values are never returned in API responses (secretRedacted = "••••••••"), and WriteOnly catalog keys (security.adminPassword, protocols.snmp.readCommunity, protocols.snmp.writeCommunity) are redacted from configuration snapshots and diffs.

Enterprise Authentication & Scoped Tokens ● Implemented

Authenticate operators via local bcrypt accounts, OIDC (Authorization Code + PKCE), SAML 2.0, LDAP / Active Directory bind, or RADIUS PAP (internal/auth/).

Three built-in roles (admin, operator, viewer) govern access. Automation clients use bearer API tokens (pm_<random>, stored as SHA-256 hashes) that can be restricted to specific device groupIds and expiration timestamps.

Append-Only Audit Log & SIEM Forwarding ● Implemented

Every login, configuration write, dry run, certificate enrollment, credential rotation, and RBAC change is recorded in the audit_log table with actor, IP, action, target, and timestamp. PrintMarshal exposes no API to edit or delete audit rows.

For tamper-evident retention outside the host database, enable real-time SIEM forwarding (internal/siem/) over RFC 5424 syslog (udp, tcp, or tls in structured-data, cef, or json format), rotating JSON-lines files, or HTTP collectors.

Network Isolation & Container Hardening ● Implemented

PrintMarshal makes zero outbound cloud calls. All web fonts and assets in the application console are bundled locally.

The official Dockerfile builds a static Go binary (CGO_ENABLED=0) on golang:1.27-alpine and runs on alpine:3.23 as unprivileged user pm (UID 10001). See Wiki: Security ↗.
