Printer Fleet Security & Configuration Console

Know where your printer fleet is exposed.

Printers hold network credentials, TLS certificates, and open management ports, yet most teams only notice them when toner runs out. PrintMarshal discovers your fleet over standard SNMP and IPP, audits device security without treating unreadable settings as passing, and previews configuration changes before writing.

Guided Product Walkthrough

From fleet discovery to verified configuration changes.

Explore how PrintMarshal discovers printers, evaluates security posture, separates research coverage from live driver evidence, and previews configuration changes. All captures come from the shipped application running against pm-sim.

Step 1 of 5 · Discover fleet
● Implemented · Read-Only

1. Discover printers and reconcile identity

Scan CIDR ranges, IP lists, or passive multicast announcements. PrintMarshal polls standard SNMP MIBs and IPP attributes for identity, supply levels, page counters, and firmware versions.

  • Identity matching: Reconciles by serial, UUID, MAC, and IP while flagging conflicts when another printer reuses an address.
  • Protected operator fields: Display names, locations, and asset tags are never overwritten by polls.
Scope: Discovery and scheduled polling are strictly read-only.

● Implemented · Security Audit

2. Assess fleet posture against the Baseline policy

Evaluate printers against the 14-item Baseline policy or custom rules covering legacy ports, SNMPv1/v2c exposure, TLS versions, and certificate validity.

  • Honest scoring: Unreadable settings report as unknown and are excluded from the score denominator rather than counted as pass.
  • Port & TLS probes: Checks management/print ports and inspects TLS handshakes on HTTPS and IPPS.
Scope: Policy assessment is diagnostic; remediation uses a separate dry-run or apply workflow.

● Implemented · Device Inspection

3. Inspect per-device findings and certificates

Drill into any printer to inspect failed checks, settings unreadable over standard MIBs, and TLS certificates presented by the device.

  • Observed vs expected: Displays the live value reported by the printer alongside the policy requirement.
  • Certificate inventory: Tracks observed TLS certificates, expiry alerts, and certificates enrolled via PrintMarshal.
Scope: PrintMarshal enrolls certificates via internal CA, EST, or SCEP; installing on physical hardware requires a vendor driver or printer web UI.

● Implemented · Capability Evidence

4. Separate live driver support from research

PrintMarshal includes a 15-vendor, 495-model research catalog, but never claims a model is supported solely from vendor documentation.

  • Observed provenance: Shows which operations answered live on the device over SNMP or IPP.
  • Unsupported reasons: Explains why firmware pushes or vendor security writes require a model-specific driver.
Scope: Zero physical models ship marked physically validated until an operator records lab qualification.

5. Preview diffs in dry-run, then verify writes

Dry-run reads live values from target printers and computes a setting-by-setting diff without writing to hardware.

  • Read-back verification: Re-reads changed keys after apply to separate verified outcomes from unverified accepted writes.
  • One-click revert: Saves prior values before writing so verified changes can be rolled back.
Scope: Standard drivers write MIB-II identity fields and writable IPP attributes; vendor security toggles require a vendor driver.

Core Capabilities

Discover printers. Investigate risk. Review changes.

Every workflow is built on standard network protocols, explicit evidence tracking, and non-destructive previews. Explore the full Features and Security breakdown for protocol and catalog details.

● Implemented SNMP v1/v2c/v3 · IPP/IPPS · mDNS · WS-Discovery

1. Discover printers and monitor fleet health

Build an accurate inventory without agents. PrintMarshal combines active CIDR/IP scanning with passive mDNS and WS-Discovery listeners, polling standard Printer-MIB, Host-Resources-MIB, and IPP attributes.

Track toner and drum levels with 30-day sparklines, page counters, tray status, and rate-limited SNMP traps while keeping operator-assigned names, locations, and asset tags separate from device-reported fields.

2. Investigate security risk and TLS certificates

Evaluate devices against the 14-item Baseline policy or custom weighted rules across PrintMarshal's 84-key canonical settings catalog (43 security-tagged keys). Active probes inspect open ports and TLS handshakes.

Generate CSRs and enroll device certificates through the built-in CA, EST, or SCEP, with automated warnings at 30 days and critical alerts at 7 days before expiry.

◐ Device-Dependent Dry-Run Diff · Read-Back Verification · Rollback

3. Preview configuration changes and verify writes

Snapshots record setting values, reporting drivers, and writability. Before applying a configuration profile, dry-run reads live values from every target printer and displays the exact diff.

When you apply changes, PrintMarshal saves prior values for one-click revert and performs a read-back poll to confirm whether the printer verified the new value or merely accepted the request.

Transparent Scope & Driver Boundaries

What works with your printers today.

PrintMarshal separates features that work out of the box over standard SNMP and IPP from operations that depend on device writability or vendor-specific drivers.

● Implemented

Works via standard protocols

Discovery, supply and counter monitoring, policy auditing, port/TLS probing, CSR & CA/EST/SCEP enrollment, RBAC, and SIEM export.

◐ Device-dependent

Depends on printer support

Writing MIB-II identity fields (sysName, sysLocation, sysContact) and writable IPP attributes (Set-Printer-Attributes) with read-back verification.

◈ Simulator-only

End-to-end on pm-sim

Firmware image delivery over POST /fw-sim is wired only for loopback simulator targets (127.0.0.1 / localhost).

◌ Requires vendor driver

Extension points ready

Physical firmware pushes, certificate installation (CertificateInstaller), and proprietary protocol toggles require a vendor driver.

Capability area Status What ships today & operational boundary
Discovery, inventory & health ● Implemented Active CIDR/IP scans, passive mDNS and WS-Discovery, Printer-MIB supplies/trays/counters/alerts, and rate-limited SNMP traps. Strictly read-only.
Security assessment & certificates ● Implemented 14-item Baseline policy + custom rules (pass / fail / unknown), TCP port & TLS probes, and CSR + internal CA/EST/SCEP enrollment. Physical certificate installation requires a vendor driver or printer web UI.
Configuration profiles & rotation ◐ Device-dependent 84-key catalog, dry-run diff, read-back verification, rollback, and encrypted credential staging. Standard drivers write MIB-II identity and writable IPP attributes; vendor security writes require a vendor driver.
Firmware repository & campaigns ◈ Simulator-only Stores SHA-256 verified images, evaluates version rules, and delivers to pm-sim on loopback. Physical printer firmware delivery requires a vendor FirmwareDriver.
Optional local CUPS queue add-on ◐ Optional Linux add-on Off by default (internal/printprovider/). Reconciles local host CUPS queues (pm- prefix) or publishes IPP Everywhere URIs for discovered printers. PrintMarshal manages devices—not print jobs, quotas, or pull-print release.
