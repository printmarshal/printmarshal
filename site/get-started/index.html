Simulator-First Onboarding

Evaluate locally with the built-in simulator.

You do not need a physical printer or a lab VLAN to evaluate PrintMarshal. Build or pull the repository, run pm-sim on loopback (127.0.0.1), and walk through discovery, Baseline security assessments, and configuration dry runs safely on your workstation.

1. Evaluate with pm-sim 2. First-Success Checklist 3. Docker & Binary Deployment 4. Environment & Ports Reference
Path 1 · Recommended First Step

Run PrintMarshal against pm-sim on loopback.

cmd/pm-sim emulates an SNMPv2c/v3 agent, an IPP 2.0 printer, and a loopback firmware endpoint (POST /fw-sim) using walk fixtures in testdata/fixtures/. With both processes bound to 127.0.0.1, background discovery/traps disabled, and zero-config unchecked during discovery, discovery and polling traffic stays on loopback.

Step 1: Build & start the simulator

Requires Go 1.27+ and Node 20+ (npm). Build the frontend and binaries, then launch pm-sim on high unprivileged loopback ports (19261 UDP for SNMP, 19231 TCP for IPP):

Terminal 1 — Build & start pm-sim 
git clone https://github.com/printmarshal/printmarshal.git
cd printmarshal
make web && make build

./bin/pm-sim \
  -fixture testdata/fixtures/generic-laser.snmp \
  -snmp 127.0.0.1:19261 \
  -ipp 127.0.0.1:19231

pm-sim supports in-memory SNMP SET on sysName, sysLocation, and sysContact plus IPP attribute queries so dry-run previews and read-back verified writes work end to end.

Step 2: Start PrintMarshal wired to pm-sim

In a second terminal, create a persistent encryption key in /tmp/pm-eval/secret.key (if not already present) and start printmarshal pointed at the simulator ports:

Terminal 2 — Start PrintMarshal on 127.0.0.1:19280 
mkdir -p /tmp/pm-eval
[ -f /tmp/pm-eval/secret.key ] || (umask 077 && openssl rand -base64 32 > /tmp/pm-eval/secret.key)

PM_LISTEN=127.0.0.1:19280 \
PM_DATA_DIR=/tmp/pm-eval \
PM_SECRET_KEY="$(cat /tmp/pm-eval/secret.key)" \
PM_ADMIN_PASSWORD=evaluate-local-123 \
PM_SECURE_COOKIES=false \
PM_SNMP_PORT=19261 \
PM_IPP_ENDPOINTS='http://%s:19231/ipp/print' \
PM_DISCOVERY_ENABLED=false \
PM_TRAP_ENABLED=false \
./bin/printmarshal

Open http://127.0.0.1:19280 and sign in as admin / evaluate-local-123. Re-running the snippet above reuses /tmp/pm-eval/secret.key so stored credentials stay decryptable.

First-Success Walkthrough

Five checks to run in your local session.

Once signed in to http://127.0.0.1:19280, follow these five steps to verify discovery, compliance scoring, and configuration dry runs.

1. Discover 127.0.0.1 Read-Only

Go to Discovery, enter target 127.0.0.1, uncheck zero-config multicast (mDNS / WS-Discovery), and click Start discovery. The simulated printer (Acme LaserPrint 4200dn) is added to your inventory.

2. Poll supplies & counters SNMP + IPP

Open the device from Devices and click Poll now. Inspect toner and drum percentages, tray status, page counters, and separate operator vs discovered identity fields.

3. Run Baseline assessment Audit

Open the device Security tab and click Assess now. Observe SNMP v1/v2c enabled failing (× Fail) while 9 settings not exposed over standard SNMP/IPP are reported as ? Unknown.

4. Preview a configuration diff Dry-Run

Open Configuration, create or select a profile (such as changing identity.contact or identity.location), and run a Dry-run preview. Inspect the live current-vs-desired diff before writing.

5. Apply, verify & revert Read-Back

Confirm the apply. PrintMarshal writes the change, re-reads the setting from pm-sim to mark it verified, and enables one-click Revert... using saved prevValues.

Stop background processes Cleanup

When finished evaluating, press Ctrl+C in both terminals and remove /tmp/pm-eval if you no longer need the test SQLite database.

Path 2 · Lab VLAN or Production Deployment

Deploy via Docker or static Go binary.

The repository Dockerfile builds the web UI (node:22-alpine) and static Go binary (golang:1.27-alpine, CGO_ENABLED=0) into an alpine:3.23 runtime image running as unprivileged user pm (UID 10001).

Preserve the encryption key across restarts

The encryption key encrypts every device credential and CA private key in the database (internal/secrets/secrets.go). It is either PM_SECRET_KEY (base64 of 32 bytes, e.g. openssl rand -base64 32) or, when that is unset, <PM_DATA_DIR>/secret.key, which PrintMarshal creates once and then reuses. Never start against an existing database with a new key: previously encrypted credentials become unreadable. Back up the key separately from database snapshots, and never paste it into logs or tickets.

Option A: Docker container with a named volume

The image runs as user pm (UID 10001) with PM_DATA_DIR=/data. With no PM_SECRET_KEY set, PrintMarshal creates /data/secret.key itself on first start (mode 0600, owned by pm) and reuses it on every later start. A named volume keeps it, so no chown, sudo or host-side key file is needed:

Build & run (no root on the host) 
docker build -t printmarshal:local .
docker volume create pm-data

docker run -d \
  --name printmarshal \
  --restart unless-stopped \
  -p 127.0.0.1:8080:8080 \
  -v pm-data:/data \
  printmarshal:local

# Bootstrap password for the "admin" account (first start only):
docker exec printmarshal cat /data/initial-admin-password

Open http://127.0.0.1:8080 and sign in as admin. The generated password goes to /data/initial-admin-password (0600), not to the log. Change it after signing in, then remove the file: docker exec printmarshal rm /data/initial-admin-password. Setting PM_ADMIN_PASSWORD on first start instead skips the file. The command is safe to repeat: an existing secret.key is never replaced, and one that exists but cannot be read stops startup instead.

Upgrade or recreate & back up the key 
# Recreate (e.g. after a rebuild): same volume, same key and data
docker rm -f printmarshal
docker run -d --name printmarshal --restart unless-stopped \
  -p 127.0.0.1:8080:8080 -v pm-data:/data printmarshal:local

# Owner-only copy of the key; keep it apart from database backups
(umask 077 && docker run --rm --entrypoint cat \
  -v pm-data:/data:ro printmarshal:local /data/secret.key \
  > printmarshal-secret.key.backup)
Host differences: bind mounts, own key, host networking
  • Host directory instead of a volume. It must be writable by UID 10001, which normally means a privileged sudo chown 10001:10001 <dir>; afterwards your own user may no longer read it. Rootless Docker and Podman remap UIDs, so check your runtime’s documentation. The named volume avoids this.
  • Key in your own secrets manager. Pass it as -e PM_SECRET_KEY=… (base64 of 32 bytes, openssl rand -base64 32) and supply the same value on every start; no file is then written. Environment values are visible to anyone who can run docker inspect. Never switch to a new key against an existing database.
  • Discovery and traps. Multicast discovery and SNMP traps need --network host on a Linux host instead of -p (see the README). The -p 127.0.0.1 form above keeps the console local to the host.

Option B: Single binary + backup script

Run the compiled binary directly under systemd with embedded SQLite (PM_DATABASE=sqlite) or PostgreSQL (PM_DATABASE=postgres + PM_DSN), and use deploy/scripts/backup.sh (/usr/local/bin/pm-backup in the container) for consistent backups:

Run binary & online backup 
mkdir -p /var/lib/printmarshal
[ -f /var/lib/printmarshal/secret.key ] || \
  (umask 077 && openssl rand -base64 32 > /var/lib/printmarshal/secret.key)

PM_LISTEN=127.0.0.1:8080 \
PM_DATA_DIR=/var/lib/printmarshal \
PM_SECRET_KEY="$(cat /var/lib/printmarshal/secret.key)" \
./bin/printmarshal

# Consistent online backup (SQLite VACUUM INTO or pg_dump -Fc):
PM_DATA_DIR=/var/lib/printmarshal ./deploy/scripts/backup.sh /var/backups/printmarshal

Terminate TLS via Caddy or Nginx in front of 127.0.0.1:8080 so PM_SECURE_COOKIES=true (the default) works over HTTPS. See Wiki: Deployment ↗.

Configuration Reference

Environment variables and network ports.

Defined in internal/config/config.go. Environment variables override settings in config.json.

Environment variable Default Purpose
PM_LISTEN :8080 HTTP listen address for the web UI and REST API. Bind to 127.0.0.1:8080 behind a TLS reverse proxy.
PM_DATA_DIR ./data Directory for SQLite (printmarshal.db), firmware blobs (firmware/), initial password, and fallback secret.key.
PM_DATABASE & PM_DSN sqlite Set PM_DATABASE=postgres and provide PM_DSN=postgres://... to use PostgreSQL instead of embedded SQLite.
PM_SECRET_KEY <dataDir>/secret.key Base64-encoded 32-byte master key (openssl rand -base64 32) for AES-256-GCM credential and CA key encryption. Must be preserved across restarts.
PM_ADMIN_PASSWORD Random in initial-admin-password Sets the initial admin password when bootstrapping an empty database.
PM_SECURE_COOKIES true Sets the Secure attribute on pm_session cookies. Set to false only for plain-HTTP 127.0.0.1 simulator testing.
PM_DISCOVERY_ENABLED & PM_DISCOVERY_INTERVAL true / 30m Controls scheduled background discovery and passive mDNS/WS-Discovery listeners (PM_DISCOVERY_TARGETS sets comma-separated CIDRs/IPs).
PM_TRAP_ENABLED & PM_TRAP_LISTEN true / :1162 Controls the rate-limited UDP SNMP trap receiver (trap.allowedSources and trap.ratePerMinute in JSON config).
PM_SNMP_PORT & PM_IPP_ENDPOINTS 161 / standard IPP paths Overrides target SNMP UDP port and IPP URL templates for local simulator (pm-sim) evaluation.
Port & Protocol Direction Used for
8080/tcp (configurable) Inbound to PrintMarshal Web console, REST API, and SSE event stream (/api/events).
1162/udp (configurable) Inbound to PrintMarshal Optional SNMPv1/v2c trap listener (PM_TRAP_LISTEN).
161/udp Outbound to printers SNMP v1/v2c/v3 discovery, supply/counter polling, and MIB-II identity writes.
631/tcp & 443/tcp Outbound to printers IPP / IPPS polling, Set-Printer-Attributes writes, and TLS certificate handshake inspection.
21, 23, 80, 515, 9100/tcp Outbound to printers Active TCP port reachability probe during security assessments (security/portprobe).
5353/udp & 3702/udp Local LAN multicast Optional passive discovery for mDNS/DNS-SD (224.0.0.251:5353) and WS-Discovery (239.255.255.250:3702).
